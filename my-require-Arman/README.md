1. How myRequire works

    1. Resolve

    Առաջին քայլում որոշվում է, թե որ ֆայլն է պետք բեռնել։ Օրինակ՝ եթե գրում ենք `require('./math')`, ծրագիրը փորձում է գտնել համապատասխան ֆայլը։ Ստուգում է `.js`, `.json` տարբերակները, իսկ եթե տրվածը պանակ է՝ փորձում է գտնել դրա `package.json`-ի `main` ֆայլը կամ `index.js`-ը։
    
    2. Create module

    Երբ ֆայլը գտնվել է, ստեղծվում է module օբյեկտ։ Այն պարունակում է `exports`, `filename` և `loaded` հատկությունները։ Սկզբում `exports`-ը դատարկ օբյեկտ է, իսկ `loaded`-ը՝ `false`։

    3. Wrap

    Եթե ֆայլը JavaScript է, դրա կոդը փաթեթավորվում է ֆունկցիայի մեջ։ Այդ ֆունկցիային փոխանցվում են `exports`, `require`, `module`, `__filename` և `__dirname` արժեքները։ Դրա շնորհիվ յուրաքանչյուր մոդուլ կարող է աշխատել իր սեփական միջավայրում։

    4. Run
    Այնուհետև գործարկվում է փաթեթավորված ֆունկցիան։ Մոդուլի ներսում գրված կոդը կատարվում է, և եթե օգտագործվել է `module.exports`, ապա դրա արժեքը փոխվում է։ JSON ֆայլերի դեպքում կոդը չի կատարվում որպես JavaScript, այլ կարդացվում և փոխակերպվում է օբյեկտի միջոցով `JSON.parse()`-ի։

    5. Cache and return

    Մոդուլը պահվում է Cache-ում, որպեսզի նույն ֆայլը կրկին պահանջելու դեպքում այն նորից չկատարվի։ Վերջում վերադարձվում է `module.exports`-ը։ Այսպիսով՝ նույն մոդուլը մի քանի անգամ պահանջելիս ստանում ենք նույն արտահանված օբյեկտը։

File resolution order
    1. Եթե տրված ճանապարհը համապատասխանում է ֆայլի անունին, ստուգում է `.js`-ը։
    2. Ստուգում է `.json` ֆայլը։
    3. Եթե ճանապարհը պանակ է, կարդում է դրա `package.json`-ը և փորձում գտնել `main`-ում նշված ֆայլը։
    4. Եթե `main` չկա կամ համապատասխան ֆայլը չի գտնվել, փորձում է գտնել պանակի `index.js`-ը։
    5. Եթե ֆայլը չի գտնվել, վերադարձնում է `MODULE_NOT_FOUND` սխալը։

Why cache is filled before execution

    Cache-ը պետք է լրացվի մինչև մոդուլի կոդի գործարկումը, որովհետև կարող են լինել circular dependencies, այսինքն՝ երկու մոդուլ կարող են իրար պահանջել։

    Օրինակ՝ A մոդուլը պահանջում է B-ին, իսկ B-ն իր հերթին պահանջում է A-ին։

    Եթե A-ն Cache-ում չլինի մինչև իր կոդի կատարումը, ապա B-ն կրկին կփորձի բեռնել A-ն, և կարող է առաջանալ անվերջ կրկնություն։

    Դրա համար մոդուլը սկզբում ավելացվում է Cache-ում `loaded: false` վիճակով։ Այդպես մյուս մոդուլը կարող է ստանալ արդեն ստեղծված `exports` օբյեկտը՝ առանց նույն ֆայլը կրկին կատարելու։

    Սա կապված է E4 առաջադրանքի հետ, որտեղ ուսումնասիրվում էր circular dependency-ի ժամանակ մոդուլների աշխատանքի հերթականությունը և այն, թե ինչու մի մոդուլը կարող է տեսնել մյուսի դեռևս ամբողջությամբ չլրացված exports-ը։

What real Node.js require() does but my version doesn't

    Իրական Node.js-ի `require()`-ը շատ ավելի բարդ է, քան իմ գրած տարբերակը։

    Իմ loader-ը չի իրականացնում Node.js-ի բոլոր հնարավորությունները։ Օրինակ՝

    - Իրական Node.js-ը կարող է բեռնել նաև built-in մոդուլներ, օրինակ՝ `fs`, `path`, `http`։ Իմ տարբերակը նախատեսված է հիմնականում իմ նախագծի ֆայլերը բեռնելու համար։
    - Node.js-ը ունի ավելի բարդ module resolution համակարգ, որը ներառում է `node_modules` պանակների որոնում, package exports և այլ մեխանիզմներ։ Իմ տարբերակը իրականացնում է միայն դրանցից մի քանիսը։
    - Իրական Node.js-ը ունի ավելի բարդ module cache-ի և սխալների մշակման մեխանիզմներ։

2. BONUS:

CommonJS-ում `__dirname`-ը և `__filename`-ը հասանելի են ավտոմատ։ Պետք չէ դրանք առանձին ներմուծել։

    ES Modules-ում դրանք ավտոմատ հասանելի չեն։ Դրանց փոխարեն օգտագործում ենք `import.meta`։
    - `import.meta.dirname` — ցույց է տալիս ընթացիկ ֆայլի պանակի ճանապարհը։
    - `import.meta.filename` — ցույց է տալիս ընթացիկ ֆայլի ամբողջ ճանապարհը՝ ֆայլի անունով։

Կարո՞ղ ենք import գրել if-ի ներսում։

    CommonJS-ում կարող ենք `require()` գրել նաև `if`-ի ներսում։
    Բայց ES Modules-ում սովորական `import`-ը պետք է գրել ֆայլի սկզբնական մակարդակում, ոչ թե `if`-ի ներսում։
    Բայց ES Modules-ում կա նաև `import()` տարբերակը, որը կարելի է օգտագործել `if`-ի ներսում։
    Այսինքն՝ `import()`-ով կարող ենք մոդուլը բեռնել միայն այն ժամանակ, երբ դրա կարիքն ունենք։

Ինչպե՞ս ենք արտահանում և ներմուծում արժեքները։

    CommonJS-ում արժեքներ արտահանում ենք `module.exports`-ով, իսկ ներմուծում՝ `require()`-ով։
    ES Modules-ում օգտագործում ենք `export` և `import`։
    Այսինքն՝ CommonJS-ում օգտագործում ենք `module.exports` և `require()`, իսկ ES Modules-ում՝ `export` և `import`։
